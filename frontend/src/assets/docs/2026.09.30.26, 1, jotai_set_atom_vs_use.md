A write atom can own this, but Jotai holds React updates until the write function returns, which would skip `flushSync` and `startTransition`. Each update has to go through the store so those callbacks still commit on time.

Yes. Navigation is now the write-only atom `navigateToPageAtom`, and the header and the Welcome "Get started" button call it with `useSetAtom`.

The write callback's `set` does not notify React until the function returns, so `flushSync` and `startTransition` wrapped around it would never see the updates and the view transition would not run. Each update goes through `getDefaultStore().set` instead, which flushes inside the callback that wraps it. That matches the previous hook: the quadrants commit synchronously before the transition to the main page, and the page change itself stays inside the transition.
